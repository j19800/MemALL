## 0. 一句话结论

**MemALL 的身份边界与读路径隔离在代码层是"空壳"。** 握手绑定的身份可被任何一次调用用 `agent_name` 参数覆盖，并被永久改写；未注册身份拿到的是**最高**读权限；`unified_search` 的 direct/fts5/vector 三个分支**根本不传 viewer**。三者叠加，任意 MCP 客户端都能读取、写入、冒充任意 agent 的私有数据。

## 1. P0 发现（必须立即修）

### R3-1 [P0] 显式 `agent_name` 覆盖握手身份 → 会话被永久改写 → 跨 agent 冒充

- **位置**：`src/memall/mcp/session_identity.py:85-90`（`identify`）、`:45-52`（`bind_session_agent`）；`src/memall/mcp/adapter.py:121-127`
- **违反**：I5（身份不可冒充）、I6（读路径可见性）
- **攻击者视角**：我是握手为 `alpha` 的合法会话。我发 `memall_read action=search query=SECRET agent_name=writer`。结果：① 读到 writer 的 private 记忆；② `get_session_agent()` 变成 `writer`，**之后所有不带参数的调用都以 writer 身份执行**（包括写入）。
- **证据**（`probe_clean.py`，隔离库，原样）：
  ```
  场景2：已握手 alpha，显式传 agent_name=writer  -> (True, "total=1 session='writer'")
  场景3：第一次(带 writer) -> total=1 session='writer'；第二次(不带) -> total=1 session='writer'
  ```
  对照组场景 4（全程不带参数）→ `total=0`，证明隔离机制本身有效，洞只在"显式覆盖"这条路上。
- **修法**：`identify()` 不因显式参数调用 `bind_session_agent()`；显式参数只在会话无身份时作为一次性回退；adapter 在会话已有握手身份时，若显式 `agent_name` 与之冲突 → 返回 403 而非"谁赢"。
- **红蓝守卫**：`src/red_blue_checks.py::duel_session_identity_is_authoritative`（FAIL）。

### R3-2 [P0] 未注册身份拿到最高读权限（与代码注释相反）

- **位置**：`src/memall/core/thin_waist.py:2624-2639` `_get_agent_read_level()`；`:2658-2671` `_filter_by_trust()`；`:2439-2440` `VISIBILITY_ORDER`/`VISIBILITY_RANK`
- **违反**：I6、I5
- **攻击者视角**：我是从未在 `identities` 表注册过的 `phantom_unregistered`。我发 `memall_read action=search`（无 agent_name）。`_get_agent_read_level` 返回 `"private"`，`VISIBILITY_RANK["private"]=4`（最大），因此 `mem_rank <= viewer_rank` 对所有行成立 → 我能读到 `trusted`/`private` 的全部记忆。
- **证据**（`probe_trust.py`，原样）：
  ```
  viewer=phantom_unregistered  read_level=private   rank=4  -> 读到 trusted 记忆=True
  viewer=alpha (在册, trusted_by=[]) read_level=shared rank=1 -> 读到=False
  ```
- **修法**：未知身份 → `"private"` 应该是**最低**读权限（rank 0 或直接拒绝）；`agent_type='human'` 的身份（老陈）也应走同一规则，不能因类型就给最高读。
- **红蓝守卫**：`src/red_blue_checks.py::duel_unregistered_identity_is_least_privilege`（FAIL）。

### R3-3 [P0] `unified_search` 的 direct/fts5/vector 三个分支不执行信任过滤

- **位置**：`src/memall/core/thin_waist.py:1870-1953`（`unified_search` 三个分支）；`:2274-2347`（`_build_retrieve_where`，viewer 逻辑在 :2309-2311，但 `retrieve()` 调用处未传 viewer）
- **违反**：I6
- **证据**（`probe_viewer.py`，原样）：
  ```
  mode=direct 无 agent_name  total=3 读到他人=['alpha','beta','gamma']
  mode=fts5  无 agent_name  total=3 读到他人=['alpha','beta','gamma']
  mode=vector 无 agent_name  total=3 读到他人=[]   (vector_search 无 viewer 参数)
  mode=hybrid 无 agent_name  total=3 读到他人=['alpha','beta','gamma']
  ```
  hybrid 分支是唯一传了 `viewer=arguments.get("agent_name")` 的（:1966），但 `agent_name` 在无身份时为空 → viewer 为空 → 过滤整段不执行。
- **修法**：所有分支补 `viewer=arguments.get("viewer") or arguments.get("agent_name")`；`retrieve()` 的 by-id 路径（:2353-2370）也要在返回前过 `_filter_by_trust`。

### R3-4 [P0] 写入侧冒充 + 会话被改写

- **位置**：`src/memall/mcp/adapter.py:118-129`；`src/memall/core/thin_waist.py:1213-1241`（`_capture_prepare_identity`，auto-register 无校验）；`src/memall/mcp/tools/memory_write.py:104-185`（`handle_update`，caller 为 None 时 ownership 门被跳过）
- **证据**（`probe_write_imp.py`，原样）：
  ```
  握手 attacker → memall_write capture agent_name=dsh → id=1, status=ok
  库里：agent_name='dsh'（归属伪造），session → 'dsh'
  ```
- **修法**：写入时 `agent_name` 必须与会话握手身份一致，冲突 → 403；`handle_update` 的 `caller is None` 路径应拒绝（None = 未认证，不是可信内部）。

### R3-5 [P0] 无身份时 `handle_update` ownership 门被跳过 → 任意行可被改写

- **位置**：`src/memall/mcp/tools/memory_write.py:120-136`
- **证据**（A3 探针）：`action=update memory_id=1 agent_name=""` → `{"updated": true}`，`agent_name` 字段也被允许改写（`gateway_rest_handlers.py:570-576` 的 `_handle_api_update` 也不剥离 `agent_name`，透传到 `core.update()`）。
- **修法**：`caller is None` → 拒绝（不是 trusted internal）；`update()` 禁止修改 `agent_name`/`level`/`category`（pinned_fields）。

### R3-6 [P0] HTTP transport `resources/read memall://memory/{id}` 无身份检查 → 任意记忆全文泄露

- **位置**：`src/memall/mcp/http_transport.py:344-377`
- **证据**（A3）：`resources/read memall://memory/1` → 200 + 完整 private 内容；两个 HTTP 客户端共享 `_handshake_agent` 全局，第二个匿名客户端收到了 dsh 的任务卡推送通知。
- **修法**：`resources/read` 必须校验 viewer；`_handshake_agent` 全局改为 per-connection。

### R3-7 [P0] `fed_publish` 任意私有记忆可被发布到共享库，`source_agent` 可伪造

- **位置**：`src/memall/mcp/federation_tools.py:106`（`retrieve(int(memory_id))` 无 viewer）；`src/memall/federation/family.py:65`（`get_family_db_path()` = `~/.memall/family.db`，**不受 `MEMALL_DB_PATH` 隔离**）
- **证据**（A3）：`fed_publish memory_id=1 source_agent="dsh"` → dsh 的 private 记忆被复制进 `shared_memories`。
- **副作用**：A3 实测时向**生产** `~/.memall/family.db` 写入了 1 行，已自行清理并验证（33 行，marker 消失）。
- **修法**：`retrieve` 必须传 viewer；`get_family_db_path()` 必须尊重 `MEMALL_DB_PATH`；`source_agent` 必须与会话身份一致。

## 2. P1 发现

### R3-8 [P1] `memall_system action=security permit` 无授权门

- **位置**：`src/memall/mcp/tools/manage.py:98-120` → `set_permission(agent_name, level)`；`src/memall/mcp/tools/__init__.py:422-576`

- **修法**：`update()` 对 pinned 字段直接拒绝（或仅允许 trusted internal）。

### R3-10 [P1] Gateway loopback carve-out：未鉴权 GET/POST 一大堆端点

- **位置**：`src/memall/gateway.py:232-296` `_auth_middleware`；`:238` `_CSRF_REQUIRED_PATHS` 仅 2 条
- **影响**：loopback 上 `/memories`、`/api/*`、`/persona/*`、`/sessions/*`、`/federation/*`、`/graph/*` 的 GET 与 `/memories`、`/memories/smart-store`、`/memories/import`、`/db/optimize`、`/db/vacuum`、`/debt/scan` 的写操作**全免鉴权**。任何能连 localhost 的进程都能读/写/删库。
- **修法**：loopback carve-out 应仅限 `/health`、`/pair`；CSRF 覆盖所有写端点。

### R3-11 [P1] `traverse`/`timeline`/`trace`/`retrieve` by-id 无 viewer/agent 过滤

- **位置**：`src/memall/core/thin_waist.py:2896`（`traverse`，返回全文）；`src/memall/core/thin_waist_search.py:582`（`timeline`，无 agent filter）；`src/memall/mcp/tools/retrieve.py:307`（`handle_trace`）；`core/thin_waist.py:2353-2370`（by-id 路径，access_count 先 +1 再过滤，且 denied 也计数）
- **修法**：所有读入口统一过 `_filter_by_trust`/viewer；by-id 路径先过滤再计数。

### R3-12 [P1] `normalize_agent_name` vs `canonical_agent` 两套归一化 + `is_disabled_agent` 的大小写/前缀绕过

- **位置**：`src/memall/core/thin_waist.py:288-328`；`src/memall/mcp/session_identity.py:34-43`；`src/memall/core/denylist.py`
- **影响**：`gateway_test` 被禁，`gateway_test2`/`GATEWAY_TEST` 是否被禁取决于匹配方向；大小写折叠不一致可能让 `Dsh` 绕过 denylist。
