# MemALL 推广话术 · 记忆 + 目标驱动协作（2026-10-28）

> **文档状态**：现行 — 对外话术；引用结论时请对照定稿，避免使用未验证的比较

> 用途：对外介绍、社群贴、BD 一页纸。核心命题——**别的 Agent 框架每次会话从零开始，MemALL 的 Agent 记得上次做到哪、下一步该谁做。**

## 一句话版本

MemALL 是本地优先的 Agent 记忆层：把「记忆」和「目标」接成闭环，Agent 不再失忆，协作不再靠人盯。

## 三句话版本

1. **记得住**——跨会话、跨 Agent 的持久记忆，FTS + 向量混合检索，中文可用。
2. **接得上**——目标拆解成带验收标准的任务卡，按归属派发，非归属者改不动。
3. **推得动**——心跳驱动 goal_tick，Agent 自己认领、推进、结单，卡住了明确 block 等人。

## 三个可验证的差异点

| 差异点 | 具体做法 | 可验证证据 |
|---|---|---|
| 记忆不是聊天记录 | 分层 L1–L11（身份/偏好/教训/决策/任务）+ 质量门 + 去重 + 时效衰减 | 单库 6000+ 条记忆，检索可按 agent/项目/层级隔离 |
| 协作有契约 | L5 任务卡：assignee、acceptance、depends_on；claim 后调度器不再催，卡住唯一可见性是实时通知栏 | 归属门（非 assignee → forbidden）、终态关提醒、重开可再提醒，均有回归守卫 |
| 目标是执行单位 | 目标 → 拆解 → 论证收敛 → 落任务卡 → 验收 → 关闭，全程留痕 | goal_lifecycle 端到端守卫全绿 |

## 竞品对照（一句话各打一枪）

- **hermes / paperclip**：记忆是附属品，没有目标与任务的生命周期，Agent 之间靠人转发。
- **clawith / agent-mcp**：工具总线做得不错，但没有质量门，记忆越用越脏。
- **通用 Agent 框架**：会话即边界，结束即遗忘；跨会话要人复述上下文。

## 常见质疑与回答

**Q：本地优先，那多机协作怎么办？**
A：记忆库本地为主，跨端/联邦查询是可选层；敏感数据不出机器，这是企业采购的硬门槛。

**Q：和向量数据库有什么区别？**
A：向量库只解决"找相似"。MemALL 解决"该记什么、记多久、谁能改、下一步做什么"——是记忆的生命周期，不是索引。

**Q：Agent 会不会乱改别人的任务？**
A：不会。写动作带 caller 门，非 assignee 一律 forbidden，仲裁走既有 supervisor 名单，不另造特权。

**Q：怎么证明不是 PPT？**
A：一条命令跑回归守卫（69 项，覆盖检索、任务闭环、目标生命周期），外加可复跑的 e2e 脚本。

## 使用纪律（写进文档，避免误解）

- claim 之后调度器不再催该任务；卡住时**唯一**可见性是每次响应附带的通知栏。
- 结单必须带证据（resolution），否则等于没做。
- 记忆按 agent 隔离；要跨 agent 召回就不要带身份过滤。
