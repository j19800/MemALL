为什么需要它

Agent 有智商，没有记忆

每一次新会话，它都不记得上周你们定过的架构决策、踩过的坑、你纠正过的偏好。 "Agent 健忘症"是 Loop Engineering 缺失的 Memory 基础设施层。

8 种类型化边

extends · contradicts · refines · cites · supersedes · related · updates · derives，附本体层级（updates ⊃ supersedes）支持泛化遍历，从 Bug 一跳直达修复 PR 与复盘。

决策弧生命周期

每条 L4 决策自动跟踪 open → in_progress → closed：L5 讨论推进、L6 反思闭合，未决策项以"债务"暴露，不会被悄悄遗忘。

📈

回声权重 Echo

引用 25% + 访问 20% + 新近 20% + 层级 20% + 质量 15%，0–100 分。被反复使用的知识自动涨权保鲜，无人问津的进入衰减与 TTL 遗忘。

🧮

真 RRF 混合检索

FTS5 词面命中与 vec0 语义近邻各取 rank，按 Σ 1/(60+rank) 融合；过滤器下推进 SQL，重排链三级降级，检索行为可用 search_interactions 遥测复盘。

🈶

中文原生

嵌入式模型选 bge-small-zh（512 维），FTS5 对 CJK 逐字注入配合二元组召回，jieba 分词 + TF-IDF 供管线内相似度计算。

🕰️

时间维度

双时态字段（valid_from / invalid_at）+ 日/周/月预聚合 + Epoch 时期分段（间隔 >48h、类目漂移等 4 规则），"上个月那段日子"查得出来。

快速开始

安装

核心包轻量、不含 AI 模型；按需加 extras（full 含可视化与 FAISS，rerank 含 CrossEncoder）。

pip install memall-os

初始化并启动

自动建库（41 个迁移）、启动网关、注册 MCP、打开浏览器。网关监听 127.0.0.1:9920。

memall quickstart     # 或 memall init && memall start

接入你的 Agent

任意 MCP 客户端加一段配置（stdio），或直连 POST http://127.0.0.1:9920/mcp。

{ "mcpServers": { "memall": { "command": "memall", "args": ["serve"] } } }

写入即进入管线；检索带回记忆、上下文、时间线与关联。

FAQ

几个诚实的回答

数据存在哪里？会上传云端吗？
全部存在本地 ~/.memall/memall.db（SQLite 单文件），网关只绑定 127.0.0.1，联邦仅在局域网配对后通信。注意：当前版本没有静态加密，请把机器本身当作信任边界。
管线需要 LLM 或联网吗？
不需要。31 个步骤全部是确定性启发式（正则、SQL、Jaccard、TF-IDF），离线可跑、结果可复现。向量嵌入用本地小模型（bge-small-zh，512 维），重排默认本地 ONNX INT8；接大模型增强属于可选外挂。
说好的"30 步管线""11 层"，代码里到底是多少？
以运行时 list_pipeline_steps() 为准：31 个核心 + 5 个可选；层级为 P0–P2 + L1–L11 共 14 级。MCP 是 7 个聚合端点、约 50 个 action——本站所有数字直接从源码核对。
百万条记忆扛得住吗？
FTS5 与 vec0 都是索引化的；当前默认路径面向十万级优化，百万级建议启用 FAISS extra 并调低同步重排。仓库内有压测与基准脚本可复现。
和 Mem0 / Letta 怎么共存？
它们可作为上层框架保留，MemALL 只做记忆底座：通过 MCP 对任意 Agent 暴露同一份记忆。规划的 MemPort 工具将支持从它们一次性迁移。
什么规模算"够用"？
单 Agent 个人助手也值得装——一次 capture 换回的是以后每次检索的上下文；多 Agent 团队收益随共享记忆数近似线性增长。
