为什么需要它

Agent 有智商，没有记忆

每一次新会话，它都不记得上周你们定过的架构决策、踩过的坑、你纠正过的偏好。 "Agent 健忘症"是 Loop Engineering 缺失的 Memory 基础设施层。

🧩

会话即失忆

上下文窗口再大也是临时的。决策、教训、偏好散落在聊天记录里，无法跨会话、跨工具复用。

📄

Markdown 记忆不够用

手写笔记没有检索质量、没有生命周期、没有关联——存进去容易，找回来靠运气，改错了没人知道。

🤝

多 Agent 各忘各的

Claude、Codex、openCode 协同干活，却互相看不到对方的结论与冲突，重复讨论、口径漂移。

核心能力

不只是存取，是一套记忆操作系统

🧠

14 级记忆生命周期

P0–P2 原始优先带 + L1–L11 生命周期层：身份、时间、流程、会话、计划、反思、教训、关系、蒸馏、整合、商业。排除链分类器 first-match 定级，CHECK 约束入库。

🕸️

原生知识图谱

8 种类型化边（refines / cites / contradicts / supersedes…）+ 上位本体泛化遍历；管线按模式与相似度自动建边，决策弧跟踪每条 L4 决策的开放与闭合。

🔍

混合检索，可解释

FTS5 全文 + sqlite-vec 512 维 KNN，真 RRF 融合（k=60）；默认走本地 ONNX INT8 重排器，无 GPU、无 PyTorch 也能重排。

♻️

31 步自进化管线

记忆入库后自动富化、分类、建边、回声评分、时期检测、反思、蒸馏、整合、衰减、归档——每步幂等、带质量门、逐步提交。

🌐

多 Agent 联邦

跨设备 UDP 发现与配对码握手，publish / query / conflicts / inject / deliver；冲突检测自动聚类矛盾记忆，跨 Agent 蒸馏产出 L10/L11。

🔌

MCP 原生

8 个聚合工具、72 个 action（另有 21 个中文别名），stdio 与 Streamable HTTP 双通道；Claude Desktop / Cursor / Cline / Qoder 三行配置即接即用。

无人值守

Agent 不醒来，记忆也能往前推

记忆系统只是"被查"的话，价值有限。MemALL 把目标、任务与唤醒做成了一套确定性驱动：状态存在库里，谁该动手、下一步做什么，由 tick 算出来。

🎯

目标编排 goals

一个目标 = 一条 L5 + category='goal' 记忆，子项是普通任务卡：拆解 → 跨 Agent 论证 → 分派 → 执行 → 验收落地。没有新表、没有工作流 DSL，只有两个环节需要 Agent 判断，其余由确定性 tick 推进。

⏰

无人唤醒 wake_claims

Agent 没有 runtime，不会自己醒来。scheduler/agent_round 周期性为每个注册 Agent 写一条 P2 提醒，下次真实会话就能看到；wake_claims 以 (agent, goal_id, action) 为主键做跨进程认领，多个 MCP 会话也不会重复唤起同一个 Agent。

🪜

任务卡闭环

讨论收敛产出 L5 任务卡，acknowledge / resolve / block 三个动作补上执行侧；执行状态与归档状态双轨分离（migration 034），做完的事不会被重复提醒，卡住的事会持续暴露。

🧱

实体与知识三元组

entities / memory_entities / knowledge_triples（migration 024）+ 管线里的 entity_extraction 步骤，把"谁—做了什么—影响哪个模块"结构化，供图谱遍历与 Agent 记忆增强使用。

📨

飞书 / Lark 桥

讨论创建、回复、收敛时以卡片消息推送到 Bot Chat；bridge/ 是带 watchdog 的常驻进程，inbox / outbox 目录做双向投递——不在终端前也能被记忆系统找到。

🪝

20 个生命周期 Hook 点

pre/post_capture · store · retrieve · search · pipeline，加 pre_step / step_ok / step_fail 与工具、会话共 20 个挂载点；插件按需订阅，不改核心代码。

记忆模型

每条记忆都知道自己是什么

知识图谱与检索

找得回，还要串得起

🛤️

8 种类型化边

extends · contradicts · refines · cites · supersedes · related · updates · derives，附本体层级（updates ⊃ supersedes）支持泛化遍历，从 Bug 一跳直达修复 PR 与复盘。

🎯

决策弧生命周期

每条 L4 决策自动跟踪 open → in_progress → closed：L5 讨论推进、L6 反思闭合，未决策项以"债务"暴露，不会被悄悄遗忘。

📈

回声权重 Echo

引用 25% + 访问 20% + 新近 20% + 层级 20% + 质量 15%，0–100 分。被反复使用的知识自动涨权保鲜，无人问津的进入衰减与 TTL 遗忘。

🧮

真 RRF 混合检索

FTS5 词面命中与 vec0 语义近邻各取 rank，按 Σ 1/(60+rank) 融合；过滤器下推进 SQL，重排链三级降级，检索行为可用 search_interactions 遥测复盘。

🈶

中文原生

嵌入式模型选 bge-small-zh（512 维），FTS5 对 CJK 逐字注入配合二元组召回，jieba 分词 + TF-IDF 供管线内相似度计算。

🕰️

时间维度

双时态字段（valid_from / invalid_at）+ 日/周/月预聚合 + Epoch 时期分段（间隔 >48h、类目漂移等 4 规则），"上个月那段日子"查得出来。

FAQ

几个诚实的回答

数据存在哪里？会上传云端吗？
全部存在本地 ~/.memall/memall.db（SQLite 单文件），网关只绑定 127.0.0.1，联邦仅在局域网配对后通信。注意：当前版本没有静态加密，请把机器本身当作信任边界。
管线需要 LLM 或联网吗？
不需要。31 个核心步骤（+5 个可选）全部是确定性启发式（正则、SQL、Jaccard、TF-IDF），离线可跑、结果可复现。向量嵌入用本地小模型（bge-small-zh，512 维），重排默认本地 ONNX INT8，并有三级降级链；接大模型增强属于可选外挂。
Agent 不会主动调用工具，这套记忆不就闲置了？
这正是"无人值守"部分要解决的：scheduler/agent_round 周期性为每个注册 Agent 写 P2 提醒记忆，wake_claims 做跨进程唤醒认领，目标的下一步由确定性 tick 算出来。Agent 下次醒来时，待办和讨论已经在等它。
说好的"30 步管线""11 层"，代码里到底是多少？
以运行时接口和源码为准（v0.1.68 逐项核对）：list_pipeline_steps() = 31 核心 + 5 可选；层级 P0–P2 + L1–L11 共 14 级；MCP 8 个聚合端点、72 个 action（+21 个中文别名）；gateway_routes.py 注册 98 条 HTTP 路由；CLI 55 个顶层命令；migrations/ 下 45 个幂等迁移。本站数字会随版本复核更新，不靠记忆写文案。
百万条记忆扛得住吗？
FTS5 与 vec0 都是索引化的；当前默认路径面向十万级优化，百万级建议启用 FAISS extra 并调低同步重排。仓库内有压测与基准脚本可复现。
和 Mem0 / Letta 怎么共存？
它们可作为上层框架保留，MemALL 只做记忆底座：通过 MCP 对任意 Agent 暴露同一份记忆。规划的 MemPort 工具将支持从它们一次性迁移。
什么规模算"够用"？
单 Agent 个人助手也值得装——一次 capture 换回的是以后每次检索的上下文；多 Agent 团队收益随共享记忆数近似线性增长。
